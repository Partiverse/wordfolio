# ADR-0005：移动客户端技术栈

- 状态：Accepted（2026-09-28，用户评审拍板 1B / 2C / 3接受）
- 决策人：用户（wordfolio 项目所有者）
- 关联：上游仓库 wordfolio-dev 的 ADR-0001~0010（本仓 ADR 编号自 0005 起延续，承接上游既定的 ADR-0004 本地优先架构）；移动端开发计划（2026-09-28 提案，已批准）

## 背景与问题

上游 ADR-0004 已锁定：客户端本地优先、发布物为 SQLite 单文件（含 FTS5）、移动优先，框架选型留待本 ADR。需决策：

1. 跨端框架（iOS / Android 双端同步交付为既定决策）；
2. 学习调度引擎的落地位置（原执行方案 M3 规划为服务端 py-fsrs）；
3. 客户端如何消费发布物 DB（打包 / 升级路径）。

候选框架：React Native (Expo)、Flutter、双端原生。

## 决策

### D1 框架：Expo (React Native) + TypeScript

- **Expo SDK 57 / React Native 0.86 / React 19 / TypeScript**（本仓脚手架实测版本）。
- 选用理由：
  - 早期原型（Downloads 版）即 React 18 + Tailwind 4 + shadcn/ui，设计系统（Amber/Taupe token、4901 行 CSS）与禅意闪卡交互可直接延续——`nativewind` + `react-native-reusables` 把 shadcn 体系带入 RN；
  - 发布物是 SQLite 单文件，`expo-sqlite` 与 ADR-0004 同构（Spike S1 验证，见 `docs/spikes/T0-spike-结论.md`）；
  - 单人 + AI 代理协作，TypeScript 单语种仓库效率最高；EAS Build/Submit 覆盖双端 CI 交付。
- 否决 Flutter：丢弃设计系统与 React 生态复用；否决双端原生：2 倍工作量，与单人产能不匹配。

### D2 调度引擎：ts-fsrs（设备端），修订原 M3 py-fsrs 规划

- 原执行方案 M3 写的是 py-fsrs（服务端）。本地优先架构下不建后端，调度必须设备端化，改用 **ts-fsrs**（FSRS 官方 TS 实现）。
- 后果：上游 wordfolio-dev 的 engine/ 若未来实现服务端出题/干扰治理，只做内容侧调度建议，不做逐卡调度；复习状态存设备端 SQLite（用户学习库与词库发布物分离，见 D3）。
- 此修订需回写上游执行方案文档（挂 T0 收尾事项）。

### D3 数据架构：发布物 DB 只读 + 学习库分离

- `wordfolio.db`（发布物）随 App 打包（assets），运行期复制到 App 沙箱后**只读打开**；edition 元数据（`meta` 表 `edition` 键）驱动版本升级：检测到新 edition 即删除重拷（词库无用户状态，可安全重建）。
- 用户学习状态（FSRS 卡片状态、收藏、每日目标）独立存 `learning.db`（设备端创建、可写），通过 `stable_id` 与发布物关联。
- 键值/状态管理：zustand。

### D4 平台交付：双端同步

- iOS（TestFlight）与 Android（APK/内部轨道）自 M-A 起每里程碑同步出包，不分先后。

## 技术栈清单

| 层 | 选型 |
|---|---|
| 框架 | Expo SDK 57 (React Native 0.86) + TypeScript 6 |
| 路由 | expo-router（文件式导航） |
| 数据 | expo-sqlite（发布物只读 + learning.db）、expo-asset / expo-file-system（DB 引导） |
| 调度 | ts-fsrs |
| 样式 | nativewind + react-native-reusables（M-A 接入）；T0 期先落 `src/theme/tokens.ts` RN 主题对象 |
| 状态 | zustand |
| TTS | expo-speech（中英双语点读） |
| 提醒 | expo-notifications（M-B 接入） |
| CI | GitHub Actions：lint + typecheck + vitest；EAS Build（需 EXPO_TOKEN，配置见 `.github/workflows/ci.yml` 注释） |

## 验证（T0 Spikes）

三个 spike 的实证结论统一记录在 `docs/spikes/T0-spike-结论.md`：

- **S1** expo-sqlite 读取发布物 `wordfolio.db` + FTS5 检索（中英 MATCH）；
- **S2** expo-speech 中英 TTS；
- **S3** DB 打包进 bundle + edition 版本升级路径。

## 后果

- 正面：设计系统与 shadcn 体系延续、单语种仓库、本地优先零后端成本。
- 负面/风险：nativewind 对 Tailwind v4 的支持仍在预览，M-A 接入时锁 Tailwind 3.4.x；expo-sqlite 的 FTS5 可用性已在 S1 实证（Android 侧随 expo-sqlite 自带 SQLite 编译，iOS 侧用系统 SQLite）；Expo Go 不含本仓自定义原生模块，若 M-C 后需要（如音频波形）则切 dev client。
